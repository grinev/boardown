## Release v0.5.3

### Board

- **Custom fields (beta)** — A board can declare extra per-task fields in `.boardown/config.yaml`, and each one becomes an editable row in the task dialog's Details card; a long value moves to the line below its label. Only the `string` type exists for now and the storage format may still change before 1.0.
- **Release files follow the release name** — Renaming a release now renames its markdown file too, so the name you see and the file on disk stay in sync instead of drifting apart after creation.
- **Finishing a release is all-or-nothing** — Completing the current release writes every file it touches or none of them, so an external edit halfway through can no longer leave the release marked finished while its open tasks are still inside it.
- **The reload prompt is reachable** — When an external change blocks a write started from a dialog, the conflict modal now comes to the front and closes that dialog, instead of opening behind it where **Reload board** could not be clicked.
- **Dragging into the Backlog no longer loses a task** — Moving a task from the current release into the Backlog keeps it on disk; in some drops it used to vanish from the board entirely.
- **Backlog drops work on a fresh board** — Moving a task with no epic into the Backlog no longer fails on a board that has never had one; the backlog file is created on demand.

### CLI

- **Custom fields** — `task add` and `task edit` set values with a repeatable `--field key=value` (an empty value clears the field), `boardown schema` lists the fields a board declares so an agent knows what it may write, and `task get` returns them.
- **Release rename** — `release edit --name` renames the release's file along with the release.
- **Atomic `release done`** — Completing a release from the CLI writes all of its files together or none of them, the same as on the board.
