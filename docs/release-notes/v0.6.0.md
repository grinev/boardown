## Release v0.6.0

### Board

- **Task search** — A search field in the top bar finds any task on the board by id, title or description; type three characters and pick a match from the dropdown to open it, finished releases included.
- **Task priority** — Every task carries one of four priorities (`Critical`, `High`, `Medium`, `Low`), shown as a coloured glyph on board cards and backlog rows, editable in the task and create dialogs, and available as a fourth backlog filter.
- **WIP limit on In Progress** — Cap how many tasks the current release may have in progress: the column header counts against the limit (`2 / 3`), and once it is reached every way into the column — drag & drop, the status dropdown, moving a task into the release — becomes unavailable.
- **Statuses change only in the current release** — A task in a future release or in the backlog shows its status as a static pill with a tooltip instead of a dropdown; moving a task keeps whatever status it had.
- **Edit an epic's colour** — The epic dialog gained a Color row: click the swatch to open the palette inline and confirm the pick with Save.
- **`priority` is now a reserved field name** — A board whose `config.yaml` declares a custom field called `priority` no longer loads; rename that field to open the board again.

### Desktop

- **WIP limit setting** — The settings popover's Board section gained a WIP limit field. Unlike its neighbours it belongs to the board, not the app: it is written to the open board's `config.yaml`.

### VS Code Extension

- **WIP limit setting** — The Settings dialog gained a WIP limit field for the In Progress column; leave it empty for no limit.

### CLI

- **`--version`** — `boardown --version` prints the CLI's version.
- **Task priority** — `--priority` on `task add` and `task edit`, a `task list --priority` filter, priority on every task summary, and the four levels declared in `schema`.
- **`epic edit --color`** — Change an epic's colour from the command line; it previously refused and told you to edit the file by hand.
- **Status refusals** — Changing a status on a task outside the current release fails with `STATUS_LOCKED` and a message naming the task's container, instead of writing a status the board would never let you set.
- **WIP limit refusals** — Any command that would put a task into a full In Progress column fails with `WIP_LIMIT` and writes nothing, and `schema` reports the board's limit so an agent can read the ceiling instead of hitting it.
