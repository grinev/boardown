## Release v0.10.0

### Board

- **Custom task types** — A board can declare its own task types in `.boardown/config.yaml` under `customTaskTypes`, each with a label, any Lucide icon, a colour and a commit prefix, and switch off any of the four built-in types under `taskTypes`; a task holding a type the board no longer offers still loads and shows as it is.
- **Several values in each backlog filter** — The Backlog's status, type, epic and priority filters now take any number of values, matching a task that has any of them, with the list staying open while you tick rows and the trigger reading `2 selected` once more than one is chosen.
- **Link to tasks in finished releases** — The Linked tasks section can now add and remove a link to or from a task in a finished release, which appears in the link search like any other task, while everything else about an archived task stays frozen.
- **Status changes outside the current release** — A new **Allow status changes outside the current release** checkbox in Settings lets a task's status be set from its dialog wherever it sits — the backlog, an epic or a future release — while finished releases stay frozen.
- **Full release description on hover** — Hovering the one-line release description in the Board header shows the whole description as a tooltip, with its line breaks kept.
- **A board records the boardown version it needs** — A board saved by this version notes the oldest boardown that reads it correctly, and a build older than that shows a screen asking to update boardown instead of opening the board with parts of it missing; boardown v0.9.0 and earlier cannot open a board once v0.10.0 has written to it.

### Desktop

- **Status changes outside the current release in the sidebar settings** — The sidebar's settings gained the same checkbox, next to Git integration.

### CLI

- **Custom task types** — `--type` on `task add`, `task edit` and `task list` accepts the board's enabled types, and `schema` lists each type with its label, icon, colour and commit prefix, plus the accepted icon names as `iconNames`.
- **Several values per `task list` filter** — `--status`, `--type`, `--priority` and `--epic` each accept more than one value, as `--type bug docs` or a repeated flag, matching any of them within a flag and all flags together.
- **Batch checklist edits** — `task checklist add` takes several texts and `done`, `undone` and `rm` take several item ids in one all-or-nothing call, `task add` accepts a repeatable `--checklist`, and the acknowledgement is now `{ id, items }`.
- **`task get` with several ids** — `task get BD-1 BD-2 BD-9` returns `{ tasks, missing }`, listing ids that name no task in `missing` with a successful exit instead of failing with `TASK_NOT_FOUND`, for one id as for several.
- **Links to tasks in finished releases** — `task link add` and `task link rm` no longer refuse with `ARCHIVED` when either task sits in a finished release, and `task rm` also removes the deleted task's links from finished releases.
- **`statusOutsideActiveRelease`** — With the key set in `config.yaml`, `task status`, `task edit --status` and `task add --status` succeed outside an active release instead of refusing with `STATUS_LOCKED`, and `schema` reports the setting.
- **`VERSION_TOO_OLD`** — A board that needs a newer boardown is refused by every command that reads it with this code, naming the required and the running version; `boardown init` records the requirement in the config it writes.

### Web

- **Boards that need a newer boardown** — The project list names a board that requires a newer boardown instead of reporting its config as invalid.
