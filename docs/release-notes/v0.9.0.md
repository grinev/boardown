## Release v0.9.0

### Board

- **Commits panel in the task dialog** — A task now lists the commits from the local repository whose subject names its id, newest first, each with its subject and the date it was made; a **Git integration** checkbox in Settings, on by default, turns the panel off.
- **Copy commit message** — A copy button next to the task's id in the dialog header puts a single line such as `feat(BD-123): Add next button` on the clipboard, mapping the task's type to `feat`, `fix`, `docs` or `chore`.
- **Clickable external links** — An `http://` or `https://` URL written in a task description or note, an epic or release description, a custom field value, a doc page or a repo file preview now opens in the system browser, exactly where doc and repo links are already clickable.
- **A file the parser could not read is never rewritten** — When a task block's frontmatter is broken, the write is refused and a **File cannot be written** modal names the file and lists its problems verbatim, instead of silently dropping the block; every other file on the board stays editable.

### Desktop

- **Git integration in the sidebar settings** — The sidebar's settings gained the same checkbox, under the board's other settings.

### CLI

- **`task commits <id>`** — Returns the commits from the local repository that name the task, as `{ state, commits }`; a project outside a repository, or a machine without Git, is a successful empty result rather than an error.
- **A write that would lose a broken task block is refused** — Any command that would rewrite a container holding a task whose frontmatter does not parse now fails with `UNREADABLE_FRONTMATTER`, naming the file to fix by hand.

### Web

- **Serve a board over HTTP** — `boardown-web`, installed locally from a packed tarball, serves a board on `127.0.0.1` with the same UI every other shell mounts, so a browser tab is enough to work the board; `--data-dir` names it and `--port` pins the port.
- **A registry of projects** — One server can serve several boards, each at `/b/<id>/`, with a list page at `/` naming them; started with no argument it reads a per-OS default registry file, so nothing has to be typed to start it.
- **Add and remove projects on the list page** — The list page gained an `Add a project` form and a `Remove` control per row, which patch the registry file a line at a time and leave every other byte, comments included, untouched; removing a project deletes nothing on disk.
- **Auto-refresh on external changes** — A change made by git, the CLI or an editor under the board's `.boardown/` updates the open tab in place — no page reload, no loading screen, dialogs and scroll position kept — as it already does in VS Code and Electron; `--no-watch` turns it off.
