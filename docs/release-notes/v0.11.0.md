## Release v0.11.0

### Board

- **Attachments** — A task dialog's new **Attachments** section, below Description, takes any number of files from the system file picker (up to 25 MB each), keeps them in `.boardown/attachments/<task id>/`, opens each in the same preview as a repo file link, and offers **Download** and **Delete** from each row's `…` menu; Create task can attach files too.
- **Image previews** — An image attachment shows a thumbnail in its row, and an image — attached or linked with `[[repo:…]]` — now opens as a picture in the file popup instead of `Unsupported file format`.
- **Labels** — Tag a task with free-form labels, shown as chips on its board card and edited in a **Labels** row of the task dialog and in Create task, with suggestions drawn from a board-wide list in `.boardown/config.yaml` that grows as you add new labels.
- **Link tasks while creating them** — Create task gains a **Linked tasks** section, so a new task is created already linked to the tasks you picked, under any of the seven relations.
- **Edit finished releases** — A new **Allow editing finished releases** checkbox in Settings lets a task in a finished release be edited, moved, deleted or created there, and the release's own name and description be changed, while the release itself stays in the Archive.
- **The backlog lives in one file** — Every task in no release is now kept in `.boardown/backlog.md`, so backlog changes stay small in git diffs; an existing board is converted by the first change made to it, a one-time notice says so, and builds older than v0.11.0 can no longer open the board after that.

### Desktop

- **Edit finished releases in the sidebar settings** — The sidebar's settings gained the same **Allow editing finished releases** checkbox.
- **Download an attachment through a Save-as dialog** — An attachment's **Download** asks where to save the copy with the system's own dialog.

### VS Code Extension

- **Download an attachment through a Save-as dialog** — An attachment's **Download** asks where to save the copy with VS Code's own Save dialog.

### CLI

- **`boardown skill install`** — Install the boardown agent skill, carried inside the CLI itself, for `claude`, `codex`, `opencode` or the shared `agents` folder, in the project or with `--global` under your home directory, reporting each file as `created`, `updated` or `unchanged`.
- **Attachments** — `task attachment add`, `rm` and `ls` manage a task's files, `task add --attach` creates a task with files in one all-or-nothing write, `task rm` removes the task's attachments too, and `schema` reports the 25 MB cap.
- **Labels** — `task add --label` and `task label add` / `rm` set a task's labels, every task listing carries them, and `schema` reports the board's labels and the 28-character limit.
- **`task add --link`** — Create a task already linked to others, as `--link BD-7` or `--link blocks=BD-9`, with the task and every link landing in one write.
- **`editFinishedReleases`** — With the key set in `config.yaml`, commands that edit, create in, move into or out of a finished release succeed instead of refusing with `ARCHIVED`, and `schema` reports the setting.
- **The backlog in one file** — `task list --backlog` now returns every task in no release, and a task's location reads `in.kind: "backlog"` with `in.file` naming the file that holds it, in place of `kind: "epic"`.
- **Quoted epic colour** — `schema`, `help` and the usage errors print `--color "#rrggbb"` quoted so a copied command keeps its colour, and `epic add` with a bare `--color` now fails with `USAGE` instead of silently using the default colour.
