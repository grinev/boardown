Give packages/web a second role next to the Vite dev shell: a local HTTP server that serves the built @boardown/ui over the same /api/fs contract, so a board can be opened in any browser tab without a checkout of the repo at runtime.

Modes

- `boardown-web --data-dir <path>` serves one board. With no flag the board is the .boardown of the current directory. URL is /.
- `boardown-web --registry <file>` serves several boards from one process. URL is /b/<id>/ per board, and / renders a plain server-rendered list of the projects with links. No implicit default registry location: the flag always takes a path.

Registry file

A mapping of id to absolute path:

    projects:
      boardown: D:/Projects/AI/boardown
      shop: D:/Projects/work/shop

The id is written by the user, so it is stable across edits of the file and readable in a URL that has to survive a browser restart. The display name of each project is read from that board's config.yaml, not duplicated in the registry. The file is re-read when its mtime changes, so adding a project does not require a restart.

Server

- The whole app mounts under a prefix, and /api/fs/{read,list,stat,write} lives inside it: /b/<id>/api/fs/read?path=... Single-board mode is the same thing with an empty prefix, and DevHttpFsAdapter takes a base URL.
- A board root is only ever resolved from the process arguments or the registry, never from the request; the request carries a registry id and a path relative to the resolved root, and the existing containment check stays.
- Binds 127.0.0.1 explicitly and prints the URL it actually listens on. Checks Origin and Host.
- Default port 0; --port pins one.
- The /api/fs handlers live in one module inside the package, parameterized by how a request resolves to a board root: the Vite dev middleware mounts it single-board, the server mounts it in either mode. One contract, two hosts.
- Manual Reload only; no watcher, no SSE.

Packaging

- Bin name is boardown-web. The package stays private: true — installation is a local npm pack plus a global install of the tarball, not npm publish.
- @boardown/core, @boardown/ui, react and react-dom move to devDependencies and are bundled, the same pattern packages/cli already uses. Nothing is resolved at install time.
- files: [dist, bin] plus a prepack that builds, so the tarball never ships an empty dist. Dev-only code (the Vite plugin, the log file sink) is not reachable from the server entry.
- The dev shell stays single-board on --data-dir.

Docs

CLAUDE.md and PRODUCT.md describe packages/web as a dev-only shell. Both need a sentence about the server role.

Out of scope: publishing to npm, auto-refresh, a project switcher inside the board UI.
