## Write completeRelease's files through writeAll

---
id: BD-65
type: tech
status: done
order: 500
---

completeRelease writes each changed container with its own fs.write, so a failure or an external change halfway through leaves the board half-moved. Switch it to the guarded writeAll, the way moveTaskOnBacklog does since the issue #8 fix. The 'find the container by filename and serialize it' block is duplicated verbatim in both places by then, so extract a shared filename -> GuardedFile resolver at the same time.

## Conflict modal opens behind the dialog that triggered it

---
id: BD-69
type: bug
status: done
order: 600
---

When the external-change guard refuses a write while a dialog is open (Complete release, and any other dialog that survives a failed submit), the store opens the Reload conflict modal, but the triggering dialog stays on top of it: both are showModal() dialogs, so the user sees only the inline error and cannot reach 'Reload board' until they cancel the dialog by hand. The board itself is left correctly untouched, so the flow is recoverable but has no visible affordance. Found while manual-testing BD-65; it predates that change and is not specific to release completion.
